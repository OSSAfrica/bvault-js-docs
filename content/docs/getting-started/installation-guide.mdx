## Browser requirements

Use a secure context (HTTPS, or localhost for development) with Web Crypto, localStorage/sessionStorage, and IndexedDB available. Storage can be blocked by browser policy, private browsing, or an embedded context. Handle initialization failures rather than relying on a historical browser-version table.

The library's current development source now has native browser checks across Playwright Chromium, Firefox, and WebKit, including cross-tab lifecycle cases. This coverage applies to the tested source rather than retroactively certifying stable 0.3.4. See [browser coverage](/docs/next/development#browser-coverage).

The library's browser requirements are separate from the Node version used to build this documentation website. The website uses Node 24.

## Server rendering

The **0.3.4 published build reads browser storage at module scope**. In an SSR framework, dynamically import it on the client. Do not place a static import in a server-rendered component or execute storage operations in Cloudflare Pages build code.

The published 1.0.0-preview.1 package is safe to import under SSR, but storage operations still require a browser. See the [preview](/docs/next); this import behavior does not apply to 0.3.4.

## TypeScript and bundlers

Types ship with the package. Use a bundler that understands ES modules and include DOM types for browser code. The library's standalone bundle tooling is now fixed on main: it builds a browser ESM bundle used by the working playground. See [bundle tooling](/docs/next/development#bundle-tooling) for the source workflow. A published CDN/minified-bundle URL is not a supported installation path in these stable 0.3.4 instructions.
